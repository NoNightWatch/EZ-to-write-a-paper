# 连续案例的材料包 / Continuous case evidence packet

**全部材料均为原创虚构教学材料。All materials are fictional and created for teaching.** 没有真实机构、参与者、观察研究或可引用的外部论文。练习的目标是追踪材料到文字的过程。读完这些材料即可做练习，无需联网、安装软件或另找数据。

## P01：任务记录 / Project record

虚构的学习中心改写了六张服务说明卡。材料包保存每张卡的 earlier 和 later 两版完整文字，共 12 份文档。六对材料是练习预先提供的全部材料，未从更大的总体抽样。两版只表示顺序，没有具体日期。没有随机分配、读者测试、耗时、满意度或理解成绩记录。

A fictional learning centre revised six service cards. The packet contains the complete earlier and later text of each card: six pairs, twelve documents. These are all materials supplied for the exercise, not a sample drawn from a larger population. The version labels indicate order only; dates are unavailable. No random assignment, reader testing, completion times, satisfaction ratings, or comprehension scores are supplied.

问题 / Question: How do the number of numbered items and the presence of an explicit contact line differ between the two versions of these six cards?

## P02：计数口径 / Counting rules

- 单位：一张卡的一个版本。比较单位：同一卡的版本配对。Unit: one version of one card; comparison unit: one paired card.
- `numbered items`：正文中带数字编号的顶层条目数。一个编号内有多个动词仍只数 1 项。标题与 Contact 行不计入。Count top-level numbered items; several verbs under one number still count as one item. Exclude titles and contact lines.
- `contact line`：出现以 `Contact:` 开头的独立行就记 1，否则记 0。这只说明版面上有该行，未验证地址是否有效或帮助是否可得。Record 1 for an explicit separate line beginning `Contact:`, otherwise 0. No address or service availability is verified.
- 描述全部六对材料的总数、每张卡均值和逐对变化。相对变化以 earlier 总数为分母。Describe totals, means per card, and paired changes. Use the earlier total as the denominator for relative change.
- 练习按给定规则人工逐项计数；没有双人独立编码、信度系数或推断检验记录。Do not claim independent dual coding, reliability statistics, or inferential testing.

## P04：给讨论使用的作者解释 / Supplied author interpretation

查看 C01 的选房间与时段、C06 的取回执等原句，可以看到一些 later 条目把 earlier 中分开的动作合在同一编号内。可将其描述为版面分组变化。不能据此推出任务本身减少、读者更快或服务效率提高。

Some later items combine actions that had separate numbers, as visible in C01 and C06. This supports an interpretation about grouping on the page. It does not establish fewer underlying tasks, faster readers, or more efficient service.
