## 1. 先理解你下载的是什么

PAPER QUEST 是一套可由你与 AI 助手共同使用的学术写作指南，包含写作流程、术语、教程、期刊参考与可选查词工具。可让助手根据当前稿件按需读取，也可以直接作为 Markdown 教材自学。

你需要准备：

- 能读取指南及稿件的 AI 助手。
- 一段文字、笔记、提纲，或你有权提供的文献。没有材料也可以先用明确标注的虚构例子练习。
- 目标期刊如已确定，给出刊名与文章类型；未定也可以开始。

无需先安装 Python。脚本只用于可选查词和维护检查。AI 服务本身的账户、费用、联网与隐私设置由对应服务提供方管理。

<a id="try-without-install"></a>
### 先体验，不动原稿和配置

下载并解压完整包，把文件夹放进助手可读取的工作目录。打开 `START-HERE.zh-CN.md`，或直接发：

```text
读取 academic-manuscript-polish/SKILL.md 并按流程工作。
先确认入口和所需资料能读取，不安装、不修改配置。
使用该指南文件夹内 assets/first-session-demo.md 的虚构段落试用。
英文修订，中文解释，暂不保存文件。
```

这是通过文件访问试用，原生技能尚未安装。工作目录不同就提供实际路径。若聊天工具无法读取文件夹，应提供相关内容或改用支持本地文件的助手，不要把“已经知道这个技能”当成加载成功。

你应得到干净稿和两处解释，人数及陈述归属保留。再要求“第一句恢复，第二句保留”，看看修改是否符合自己的习惯。参考输出见[虚构试用稿](../academic-manuscript-polish/assets/first-session-demo.md)。无需提供私人论文。

<a id="install"></a>
## 2. 下载与安装

### 下载完整包

[直接下载 `academic-manuscript-polish.zip`](https://github.com/NoNightWatch/EZ-to-write-a-paper/releases/latest/download/academic-manuscript-polish.zip) 并解压。这个入口指向最新发布包；版本在文件夹内 `bundle-manifest.json` 的 `version` 字段查看。也可在仓库首页选择 **Code → Download ZIP**，从中取出 `academic-manuscript-polish` 文件夹。

不要仅复制 `SKILL.md`。其他资料通过相对路径加载，需要保留目录层级。ZIP 是压缩包，必须先解压后使用本地目录安装方式。

### 选择一个安装范围

| 助手 | 只供当前项目使用 | 供个人多个项目使用 |
| :--- | :--- | :--- |
| Codex | `<项目>/.agents/skills/academic-manuscript-polish/` | `~/.agents/skills/academic-manuscript-polish/` |
| Claude Code | `<项目>/.claude/skills/academic-manuscript-polish/` | `~/.claude/skills/academic-manuscript-polish/` |

`~` 表示当前用户的主目录。Windows 可在资源管理器地址栏输入 `%USERPROFILE%` 后找到主目录；macOS/Linux 通常为当前用户的个人目录。`<项目>` 要替换成你实际打开的工作文件夹。通常选择一种安装范围即可，避免加载多个同名版本。

项目内安装示例：

```text
my-paper/
  draft.md
  .agents/
    skills/
      academic-manuscript-polish/
        SKILL.md
        START-HERE.zh-CN.md
        START-HERE.en.md
        references/
        assets/
        scripts/
        tests/
        agents/
        README.md
        bundle-manifest.json
```

Claude Code 项目对应的目录名为 `.claude`。确认 `SKILL.md` 直接位于 `academic-manuscript-polish/` 里，避免多套一层同名文件夹。

路径于 2026-10-18 对照 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)和 [Claude Code 官方文档](https://code.claude.com/docs/en/skills)核对。组织策略、云会话与本地会话可能采用不同加载方式，请以宿主当前说明为准。

### 确认助手能读到

在安装位置对应的项目中启动会话，尝试：

- Codex CLI / IDE：`$academic-manuscript-polish`；桌面端使用宿主技能选择器或自然语言请求。
- Claude Code：`/academic-manuscript-polish`

也可用自然语言说明：“请读取已安装的 academic-manuscript-polish，按它的流程处理下面的段落。”若列表尚未更新，开启新会话后检查。请助手说明实际读取的入口路径；只回答“我知道这个技能”不足以确认加载成功。

其他助手可以读取完整文件夹时，请直接指定 `SKILL.md` 的位置。如果它只能接收聊天文字，可手动提供入口和当前需要的资料，但这种方式无法保证自动读取所有相对链接。普通聊天界面与原生技能安装的能力范围可能不同。

### 想让助手帮你复制文件？

对可操作本地文件的 Codex 可发送以下请求。Claude Code 对应的项目目录为 `.claude/skills/`。

```text
请把我已解压的 academic-manuscript-polish 完整文件夹
安装到当前项目的 .agents/skills/ 中，不改其他设置。
先确认源目录和目标目录；已有同名目录时先报告版本和差异，
不要覆盖、删除或合并。完成后核对文件完整性并报告版本与入口路径。
```

这一请求授权复制到指定目录，下载操作本身不包含这项授权。首次使用先选项目范围，只有希望跨项目使用时再采用个人目录。

<a id="first-session"></a>
## 3. 第一次使用：先给一个段落

复制这段话，把括号替换成你的信息：

```text
请使用 academic-manuscript-polish。
我是学术写作初学者。

我的材料：［粘贴一个段落，或给出可访问的文件］
目标期刊：［刊名 / 未定］
本轮范围：只处理这一个段落。
正文语言：［原稿语言 / 英文 / 中文］
解释语言：［中文 / 英文］

先给可用修订，再解释两处最重要的改动。
保留数字、引文和原意。不要补写研究事实。
专业含义有疑问时请问我。
```

正常交付应包括修订段落、少量重要解释，以及确实影响修改的问题。原句已经清楚时可以保留。你不需要接受每项改动，可以要求恢复某个词、降低改动幅度，或解释为什么需要改。

如果输出与原意有差异，直接指出：“这里的 X 指的是……，请恢复这个定义，其余部分保留。”

不想填上面的信息时，一句“只润色这一段，保留原意”即可。默认保持片段的内容与结构，修订沿用原稿语言，解释沿用当前对话语言；期刊可以之后再补。

<a id="one-clear-thing"></a>
### 先说清一件事

如果一想到整篇论文就难以开始，可以打开[中文短入口](../academic-manuscript-polish/references/one-clear-thing.md)，或直接发：

```text
请用“先说清一件事”带我开始，中文讲解。
先别展示整篇课程、术语目录或期刊要求。
先问我材料里的一件事，让我用普通话或几个词回答。
使用我的回答，指出已经写清的内容，只补当前一个关键点。
我可以随时要求示范、直接改稿或暂停。
```

有现成句子就用现成句子，无需重新做一遍。有材料时整理一个观察；只有选题时先形成一个问题；没有材料时可选虚构例子。不能为完成任务而编造结果。

助手会说明这句话可承担什么用途，保留能用的表达。数字、单位或出处缺失时，只问当前需要确认的内容；语言粗糙可以逐项修改。它不会给总分、倒计时，或要求一次补完全文所有内容。

完成一句就可以停。愿意继续时再补一个来源、添一句相关信息，随后按实际需要展开段落和课程。要求完整课程时可直接进入，已确认内容无需重复提交。这个入口用于帮助开始写作，不作心理诊断，也没有经过情绪或学习效果实验。

<a id="first-paper"></a>
### 从零学写整篇论文

已有稿件可以直接修改。希望系统练习时，打开[整篇课程](../academic-manuscript-polish/references/first-paper-course.md)，无需先提供私人材料。课程用六对虚构服务说明卡演示一篇完整的描述性比较论文，所有原文和计数定义都随包提供。

```text
请读取完整论文课程 first-paper-course.md。
我从未写过论文，先用虚构案例学习，用中文讲解。
从中文练习册的 E01 开始，一次只给当前任务。
让我先尝试，再指出具体位置、依据和一个改进动作。
我卡住时给提示；我要求答案时直接给。
不要把教学数值或文献放进我的真实论文。
```

| 你想怎么开始 | 打开什么 |
|---|---|
| 自己先试，再看反馈 | [中文练习册](../academic-manuscript-polish/references/paper-workbook.zh-CN.md)，含 E01 至 E08 与 T01 |
| 先看同一篇怎样逐节写 | [连续带写](../academic-manuscript-polish/references/paper-case-walkthrough.md) |
| 想通读一篇完整成稿 | [完整英文范文](../academic-manuscript-polish/references/paper-case-manuscript.md)，含摘要、各节、结果表和参考资料 |
| 写不下去，不知道该找什么 | [材料缺口桥接](../academic-manuscript-polish/references/missing-materials.md) |

八阶段依次完成事实清单、问题和提纲、方法、结果、引言、讨论和结论、标题摘要、全文核对。每轮反馈指向学生原句和具体材料；重写后再核对。题目与[参考答案](../academic-manuscript-polish/references/paper-answer-key.md)分开存放，答案可随时索取。

最后换一组活动通知记录练习。新数据有不同方向，且不提供原文，需要调整结论并说明访问范围。记录本次哪些动作自己完成、哪些用过提示即可；完成题目不等于证明掌握所有研究和写作能力。

转到自己的稿件时，提供实际材料，按其研究类型安排章节。此案例只是一个体裁；数学、历史、综述等有各自组织方式。虚构数据不可投稿。教程尚无真实学生学习效果验证。只想直接改稿时可随时退出练习，无需完成课程。

<a id="controls"></a>
## 4. 选一种合作方式

| 你的时间与需求 | 可以这样要求 |
| :--- | :--- |
| 赶时间 | “直接给修订稿，只问会影响正确性的问题。” |
| 想理解修改 | “先改好，再解释最重要的两三处。” |
| 想自己学会 | “先示范一句，再给一个可选练习和参考答案。” |

随时可以切换。练习可以跳过。导师教学的选择不自动授权重排全文或增加讨论。

修改权限也要说清楚：

- **语言修改**：语法、拼写、用词、指代和句间衔接，保持内容。
- **结构修改**：允许调整已有段落或章节顺序，要求保留对应关系。
- **依据材料形成初稿**：只整理已提供的事实、解释与文献，缺口列给作者。

只有选题时，可请求工作提纲或材料清单。若没有数据或结果，助手不能把预想写成已经完成的研究。

### 用普通话控制输出

| 你想调整什么 | 可以直接说 |
| :--- | :--- |
| 先做诊断 | “只指出两处最影响理解的问题，先别改文件。” |
| 保留声音 | “保留我的措辞和段落顺序，可选风格建议另列。” |
| 比较改动 | “先给可复制的干净稿，再列关键改前改后。” |
| 恢复一句 | “这版的第二句恢复为原稿，其余保留。” |
| 降低讲解量 | “只解释这次最重要的一处，不给练习。” |

局部恢复依赖可访问的原稿。无法确认版本时，重新提供原句即可。纯文本差异表与 Word 原生追踪修订不同；后者需要宿主具备对应文件能力并实际生成。详见[修改控制](../academic-manuscript-polish/references/session-controls.md)。

<a id="field-style"></a>
### 让表达贴近本领域，也保留自己的声音

可以要求自然、贴近本领域成熟论文的学术表达。助手会具体检查主语承接、句子主干、限定位置和段落节奏，保留清楚的长句，合并重复起头，也保留承担转折或范围提醒的短句。没有统一的句长分数，不会为了简洁删去条件或引用。

```text
请按本领域成熟论文的表达方式润色这一段，保留我的语气。
不要机械拆短句；需要时合并重复主语，保留全部信息和限定。
可参考这些论文的对应章节：［可选，提供材料或链接］。
先给一版干净稿，再解释两处句子保留、合并或拆分的理由。
```

有样文时，使用同领域、同体裁、同章节的实际文本；只读到摘要就只校准摘要。没有样文也能开始，但应说明尚未做领域校准。作者姓名或单位无法证明其母语和语言质量。期刊明确要求、一般建议与样文观察分别处理，已经写得清楚的句子可以不改。

例如，`We examined X. We compared Y. We reported Z.` 在主体与条件一致时可合成 `We examined X, compared Y, and reported Z.`；主体不同或引用范围改变时就需要保留区分。详细的[判断流程](../academic-manuscript-polish/references/field-natural-style.md)和[八组示例](../academic-manuscript-polish/references/field-style-examples.md)随包提供。讲解可以简单，稿件仍按目标读者保留专业信息。

## 5. 让术语匹配你的稿件

给出研究对象、核心问题和相关段落，通常比只报一个学科名称更有用。跨学科任务可同时使用主领域与必要的交叉领域。

```text
这段属于电池材料研究。SOC 在本文中指 state of charge。
请核对缩写和术语一致性，保留作者定义。
不要套用其他领域同名术语的释义。
```

52 个入口是基础覆盖。遇到缺词、专门定义或小众学科，提供你有权使用的参考文献，并说明希望参考术语、体裁还是段落组织。助手应记录来源、阅读范围与适用条件；样文中的事实不能直接挪入你的论文。

作者提供的文献与临时词表默认供当前稿件使用，不自动加入共享包。词表中的工作释义不应冒充标准原文。

### 同一个意思，本领域怎样表达

[学科用词资料](../academic-manuscript-polish/references/usage-selection.md) 提供 208 组对照，覆盖全部 52 个入口。每组说明候选词、搭配对象、选择条件、原创例句和替换边界。例如重新构建软件可用 `rebuild a project`，重组组织可用 `restructure an organization`；渔业也有 `rebuild a stock`。先判断句子中的实际动作，学科名称本身不能决定用词。

```text
请检查这段的研究动词和搭配是否符合本文对象。
对 restructure、rebuild、reconstruct 等近义词说明选择原因。
保持专业含义和结论强度；原词合适就保留。
可参考我提供的同领域论文，但不要把少量例子说成全领域偏好。
```

可在包根目录运行 `python scripts/search_usage.py "rebuild" --exact --format text`，加 `--domain n10` 可限定计算机入口。不会命令行也可以直接让助手查资料。例句展示编辑选择，没有建立“母语者常用词”的频率排名。

<a id="review"></a>
## 6. 文献综述怎么用

先说明你要写的是哪种任务：引言的一段、学位论文的一章、独立综述或相关工作章节（related work）。小段任务可以从几篇已有材料开始。

```text
下面是我已读的文献和笔记。我要写引言中的一个综述段。
整理问题是：［具体问题］。
请记录每篇实际读到的范围，比较共同点和差异，
再写一段能追溯来源的文字。缺少支持的关系请列出。
不要把有限材料称为系统综述。
```

建议按以下顺序推进：

1. 确定一个可回答的整理问题。
2. 区分全文、部分正文、摘要与二手引述，记录实际可读范围。
3. 为这个问题选比较字段，例如对象、时期、定义或研究任务。
4. 核对来源能支持哪项具体主张，避免一条引文承包整个复合句。
5. 组织段落，分别表达材料间的一致、差异与限制。
6. 回查出处、引用归属和尚未解决的缺口。

独立系统综述、范围综述等有相应方法要求。报告清单不能代替实际检索与筛选过程。可从[完整练习](../academic-manuscript-polish/references/review-worked-example.md)学习基本操作，再看[历史、哲学、数学及计算机与工程练习](../academic-manuscript-polish/references/review-transfer-cases.md)。其中示范材料为虚构，不可作为真实文献引用。

## 7. 目标期刊怎么提供

给出完整刊名、文章类型与官方作者指南链接。可补充少量与你的文章类型相近的已发表样文，并说明参考范围。

```text
目标期刊：［刊名］；文章类型：［类型］。
官方指南：［链接或文件］。
这轮只检查摘要、标题与关键词。
请区分刊方明确要求、样文观察和未核验事项，
保留我的结论强度，不增加首创性或录用保证。
```

40 份资料卡可作为查找入口，实际要求以当前官方指南为准。需分清文章类型、初投或返修、硬性要求或建议，以及 words 与 characters。无法联网或页面不可访问时，请提供指南文件；未验证部分保留“未核验”状态。检索刊方规则只需公开信息，无需发送未发表正文。期刊适配可以调整结构、受众和篇幅，不能改变研究本身的含义。

<a id="long-drafts"></a>
## 8. 长稿、文件与下一次续接

长稿可按摘要、引言、方法、结果、讨论分批处理，并维护术语与修改清单。每批说明实际完成了哪些段落，未读章节不能标为已审查。

优先提供可编辑文字。Word、PDF、公式、图表和引用管理字段的读取与保留取决于宿主能力。若助手无法读取某张图或公式，应提供具体缺口，必要时补充清晰截图或文字；Markdown 检查通过不能证明 Word 排版已验证。

需要暂停时说：

```text
请生成续接卡：记录稿件版本、已处理章节、术语决定、
待确认问题和下一步。先放在对话里，不保存文件。
```

下次把续接卡与正确版本的稿件一起提供。需要保存时明确给出位置。助手不应承诺跨会话自动记住所有内容。

## 9. 可选离线查词

安装 Python 3.9 或更新版本后，在指南文件夹中打开终端：

```sh
python scripts/search_terms.py "validity" --exact --format text
python scripts/search_terms.py "SOC" --exact --format text
python scripts/search_terms.py "yield" --domain agronomy-horticulture
python scripts/search_terms.py --list-domains --format text
python scripts/validate_bundle.py
python -B tests/test_bundle.py
```

检索脚本只读本地资料，不调用模型或上传文字。它返回领域、释义与位置；同名术语可能有多条结果。没有命中时可以检查拼写、词形或手动查阅资料；零结果不能证明该概念不存在。

`--format text` 便于直接阅读；省略它会保留原来的 JSON 输出，供其他程序使用。

## 10. 常见问题排查

| 现象 | 先检查 |
| :--- | :--- |
| 找不到技能 | 是否已解压；`SKILL.md` 是否处于正确层级；会话是否在对应项目；组织策略是否允许 |
| 找不到参考资料 | 是否只复制了入口文件；文件夹是否完整；助手是否有读取权限 |
| 回复用了中文 | 明确要求“修订稿和解释均使用英文”；内部教材主体为中文 |
| 过度改写 | 限定为语言修改，并列出必须保留的术语、句子与论点 |
| 期刊要求看起来过时 | 要求核对当前官方指南及访问日期；不可访问时提供文件 |
| 把虚构练习当成文献 | 要求移除该引用并回查真实来源；示例仅用于教学 |
| 直接问了太多问题 | 让助手先处理可完成部分，只保留阻碍正确修改的问题 |

## 11. 交付前由作者核对

- 数字、单位、方向、时间窗、公式条件是否保留。
- 引文是否真实且支持对应主张。
- 专业定义是否符合自己的材料。
- 修订是否改变了结论强度或引入新事实。
- 投稿格式、AI 使用披露与机构要求是否已核实。
- 未完成项目是否明确标出。

请先检查宿主的数据处理规则与稿件授权范围。勿上传未经允许的保密信息，也不要在公开 Issue 中附上私人稿件。本包未附第三方论文全文；通用写作指导不代替专业判断、临床判断或高风险操作审核。

结构与检索测试覆盖词表、用词和期刊卡；课程测试核对虚构计数、计算和双语题目，页面另做中英对应检查。未测独立模型表现或教学成效。查看[课程检查](../academic-manuscript-polish/tests/paper-course-audit.md)与[用词检查](../academic-manuscript-polish/tests/usage-journal-audit.md)。

<a id="reviewer-response"></a>
## 12. 收到审稿意见以后

给出原意见、当前稿件涉及片段和你实际做过的修改。一条意见也能开始，不必先整理全部修回信。

```text
请按 academic-manuscript-polish 整理这一条审稿意见。
原意见：［粘贴］
当前稿件相关段落：［粘贴或给文件位置］
已经做过的修改：［实际内容；没做就写未做］
我希望怎样处理：［可选；尚未决定也可以］
请给回应草稿及对应稿件位置，把计划工作和可提交文字分开。
```

助手会区分已完成修改、计划处理、需要澄清、作者决定不采纳。没有真实行号时用章节和段落开头定位。对专业分歧，需要你提供判断与依据；它不会虚构实验、分析或已经完成的工作。参考[修回流程](../academic-manuscript-polish/references/reviewer-response.md)。

<a id="update"></a>
## 13. 更新旧版，保留自己的东西

1. 下载新版到另一个临时位置，先查看 `bundle-manifest.json` 的版本。
2. 确认你当前实际使用的指南目录。若做过自定义修改，先比较并另存，勿直接覆盖。
3. 将旧版本完整备份到技能扫描目录之外，防止同时加载两版同名技能。私人稿件和临时词表应留在稿件工作区。
4. 将新版完整文件夹复制到已确认的目标。避免把新文件混入残留旧文件，或多嵌套一层目录。
5. 开启新会话，让助手报告实际读取的版本与入口，并用虚构段落检查资料访问。

更新不会自动迁移你正在写的稿件。发现问题时，先停用新版，再从自己的旧副本恢复。不要让助手无提示删除备份或合并存在冲突的文件。
